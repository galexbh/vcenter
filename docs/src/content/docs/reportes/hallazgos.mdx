Cada hallazgo incluye **severidad**, **categoría**, **objeto**, **evidencia**, **sugerencia**, un **comando de verificación** (solo lectura, no se ejecuta) y un **código de regla** que permite seguirlo entre corridas.

**Severidades:** <Badge text="Crítico" variant="danger" /> requiere atención inmediata · <Badge text="Advertencia" variant="caution" /> debe planificarse · <Badge text="Info" variant="note" /> oportunidad de mejora.

## Reglas del reporte de salud

| Categoría | Condición | Severidad | Justificación |
|---|---|---|---|
| Almacenamiento | Datastore no accesible | Crítico | VMs sin acceso a disco |
| Almacenamiento | Uso ≥ 90 % | Crítico | Al completarse el espacio, vSphere pausa las VMs |
| Almacenamiento | Uso ≥ 80 % | Advertencia | Margen insuficiente para crecimiento y snapshots |
| Almacenamiento | Aprovisionamiento thin > 150 % | Advertencia | Riesgo de agotamiento si los discos crecen |
| Snapshots | Antigüedad ≥ 30 días | Crítico | Crecimiento del delta, degradación de I/O y consolidaciones prolongadas |
| Snapshots | Antigüedad ≥ 7 días | Advertencia | Un snapshot no constituye un respaldo |
| Configuración VM | Consolidación de discos pendiente | Advertencia | Discos delta sin consolidar; consumo y degradación |
| Configuración VM | Límite de CPU o memoria configurado | Advertencia | Contención artificial aunque el host disponga de recursos |
| Configuración VM | CD/DVD conectado a una ISO de datastore | Info | Impide vMotion y el balanceo de DRS |
| Configuración VM | Versión de hardware inferior a la mínima | Info | Sin acceso a funcionalidades y correcciones recientes |
| Clúster | HA deshabilitado | Crítico | Las VMs no se reinician automáticamente ante la falla de un host |

| Capacidad | RAM de host ≥ 85 % | Advertencia | *Ballooning* y *swap* |
| Capacidad | vCPU:pCore ≥ 6 | Crítico | CPU Ready elevado y latencia |
| Capacidad | vCPU:pCore ≥ 4 | Advertencia | Requiere seguimiento de CPU Ready |
| Capacidad | RAM asignada / física > 1,0 | Advertencia | Sobrecompromiso; holgura insuficiente para HA |
| Capacidad | Holgura N+1 de memoria o CPU: uso > 100 % de la capacidad restante sin el host mayor | Crítico | La carga actual no cabe si falla un host; HA no podría reiniciar todas las VMs |
| Capacidad | Holgura N+1 de memoria o CPU: uso ≥ 90 % de la capacidad restante | Advertencia | Margen escaso ante la falla de un host |
| Capacidad | Un solo host activo en el clúster | Info | Sin tolerancia a la falla de un host |
| Capacidad | Memoria recuperada por balloon en una VM | Advertencia | Presión de memoria en el host |
| Capacidad | Memoria de una VM en swap del hipervisor | Advertencia | Degradación severa del rendimiento |
| Capacidad | Memoria comprimida por el host | Info | Señal temprana de presión de memoria |
| Capacidad | Resource pool con límite de CPU o memoria | Advertencia | Contención para todas las VMs del pool aunque el clúster disponga de recursos |
| VMware Tools | No instalado o no en ejecución | Advertencia | Sin apagado ordenado, *quiesce* ni métricas del invitado |
| VMware Tools | Desactualizado | Info | Actualizar en ventana de mantenimiento |
| Certificados | Certificado de vCenter vencido | Crítico | Interrupción de conexiones y alertas de confianza |
| Certificados | Vence en ≤ 60 días | Advertencia | Planificar la renovación |
| Licencias | Licencia vencida | Crítico | Pérdida de funcionalidades |
| Licencias | Vence en ≤ 60 días | Advertencia | Pérdida de funcionalidades al vencer |
| Alarmas | Roja / amarilla / otro estado | Crítico / Advertencia / Info | Según el procedimiento de la alarma |
| Higiene | VMs apagadas | Info | Consumo de almacenamiento y licencias |

Los hallazgos de VMware Tools, VMs apagadas, consolidación pendiente, límites de CPU o memoria, versión de hardware, ISO conectada, balloon, swap y memoria comprimida se **agrupan** en una sola fila por condición.

### Códigos de regla estables

El código de regla no incluye nombres tomados de vCenter; el objeto afectado va en la columna *Objeto*. Así, una misma condición conserva su código entre corridas:

| Regla | Objeto | Antes de 1.8 |
|---|---|---|
| `snap-age` | `VM / snapshot` | `snap-age-<snapshot>` |
| `alarm` | `entidad / alarma` | `alarm-<alarma>` |
| `license` | Nombre de la licencia | `license-<edición>` |

[Compare-Report.ps1](/vcenter/reportes/tendencias/) traduce los códigos anteriores, por lo que las comparaciones con corridas previas a 1.8 siguen funcionando.

### Holgura N+1

Para cada clúster, la holgura N+1 compara el uso actual de memoria y de CPU (`quickStats` de los hosts) con la capacidad que queda al descontar el host de mayor capacidad. Solo se consideran los hosts **activos**: conectados y fuera de modo mantenimiento. El resultado se muestra en las columnas *CPU N+1 %* y *RAM N+1 %* de la tabla de capacidad; un valor superior a 100 % indica que la carga no cabe si falla ese host. Las reglas son `cl-n1-mem` y `cl-n1-cpu` (umbral de advertencia `-N1WarnPct`) y `cl-n1-single` cuando el clúster tiene un solo host activo. El control de admisión de HA desactivado se informa con `cl-ha-admission`, en la categoría Clúster.

El balloon, el swap y la compresión de memoria (`vm-balloon`, `vm-swap`, `vm-compressed`) se leen de `quickStats` y reflejan el valor **instantáneo** en el momento de la recolección. Para evaluarlos en una ventana de tiempo, junto con CPU ready y latencia, se utiliza la [revisión de rendimiento](/vcenter/reportes/rendimiento/). La regla `rp-limit` evalúa los resource pools, excepto el pool raíz `Resources` de cada clúster o host. La regla `cl-vcpu` sugiere como verificación `./scripts/Invoke-PerfCheck.ps1 -Env <entorno> -Cluster '<clúster>'`.

## Reglas de la revisión de hosts

| Categoría | Regla | Condición | Severidad |
|---|---|---|---|
| Storage | `path-dead` | Path inactivo | Crítico |
| Storage | `path-single` | Dispositivo compartido con un único path | Advertencia |
| Drift VIBs/drivers | `vib-drift` | Versiones distintas o VIB ausente en el clúster | Advertencia |
| Red física | `nic-nolink`, `nic-speed`, `nic-mtu` | NIC sin enlace; velocidad o MTU distintas entre hosts | Advertencia |
| Tiempo | `ntp-disabled`, `ntp-servers` | NTP deshabilitado (servicio `ntpd` detenido) o fuentes distintas | Advertencia |
| Logs | `syslog-remote` | Sin syslog remoto | Advertencia |
| Seguridad | `svc-<servicio>` | SSH o ESXi Shell en ejecución | Advertencia |
| Certificados | `cert-host-expired`, `cert-host-expiring` | Certificado de host vencido / próximo a vencer (por fecha de vencimiento) | Crítico / Advertencia |
| Diagnóstico | `coredump` | Sin coredump por red | Info |
| Plataforma | `platform-mixed` | Modelos distintos en el clúster | Info |

Plataforma, servicios, NTP y certificados provienen de vCenter (`object.collect` de hosts); el resto, de esxcli. Detalle en [Diagnóstico de hosts con esxcli](/vcenter/uso/esxcli/#revisión-por-clúster-host-check).

## Reglas de la revisión de rendimiento

`Invoke-PerfCheck.ps1` evalúa métricas en una ventana de tiempo (24 h por defecto). Sus hallazgos pertenecen a la categoría Rendimiento.

| Regla | Condición | Severidad |
|---|---|---|
| `perf-cpu-ready` | CPU ready p95 por vCPU ≥ 10 % / ≥ 5 % | Crítico / Advertencia |
| `perf-ds-latency` | Latencia p95 del peor host por datastore ≥ 30 ms / ≥ 20 ms | Crítico / Advertencia |
| `perf-host-cpu` | CPU p95 del host ≥ 95 % / ≥ 85 % | Crítico / Advertencia |
| `perf-balloon` | Ballooning en la ventana | Advertencia |
| `perf-swap` | Swap-in sostenido (p95 > 0) / solo puntual (máximo > 0) | Advertencia / Info |
| `perf-net-drops` | Paquetes descartados en el host | Advertencia |
| `coverage-perf-counters`, `coverage-perf-hosts`, `coverage-perf-error` | Contadores sin datos, hosts sin métricas o consultas fallidas | Info (Cobertura) |

| Parámetro | Valor por defecto |
|---|---|
| `-CpuReadyWarnPct` / `-CpuReadyCritPct` | 5 / 10 |
| `-DsLatencyWarnMs` / `-DsLatencyCritMs` | 20 / 30 |
| `-HostCpuWarnPct` / `-HostCpuCritPct` | 85 / 95 |

Fórmulas, ventanas, nivel de estadísticas y cobertura en [Revisión de rendimiento](/vcenter/reportes/rendimiento/).

:::note[Práctica habitual, no norma]
Los umbrales de sobresuscripción, holgura N+1, rendimiento y antigüedad son referencias habituales de la industria. Cuando exista una política interna de capacidad, los parámetros deben ajustarse a ella.
:::

## Catálogo de textos

Las sugerencias de cada regla, el riesgo y la referencia de cada categoría de la auditoría y las notas comunes están en `templates/findings.psd1`. Los scripts calculan la evidencia; el catálogo dice **qué hacer**. Para ajustar el tono o adaptar una recomendación a la práctica interna basta con editar ese archivo, sin tocar código.

```powershell
'ds-used' = @{ Suggestion = @{
        'Crítico'     = 'Liberar espacio ya (snapshots viejos, ISOs, VMs huérfanas) o mover VMs con Storage vMotion; …'
        'Advertencia' = 'Planificar liberación o ampliación antes de llegar al umbral crítico.'
    } }
'svc' = @{ Suggestion = 'Detener {label} y dejar la política en off; habilitarlo solo durante una ventana de soporte.' }
```

| Sección | Contenido |
|---|---|
| `Rules` | `Suggestion` por código de regla: un texto, o una tabla por severidad (`Crítico`, `Advertencia`, `Info`) |
| `Categories` | `Risk` y `Reference` por categoría (columnas *Riesgo* y *Referencia* del informe de auditoría) |
| `Notes` | Textos comunes: nota de umbrales, nota de la tabla de rendimiento y alcance de los comandos de revisión |

- **Formato:** archivo de datos de PowerShell, leído con `Import-PowerShellDataFile` (lenguaje restringido: no ejecuta código). Se carga una vez por proceso (`Get-FindingText`, `Get-CategoryText` y `Get-NoteText` en `Common.psm1`).
- **Marcadores:** `{label}` o `{window}` se reemplazan como texto literal; nunca se evalúan.
- **Estilo:** acción en imperativo, motivo breve y «cambio aprobado» cuando la acción modifica la plataforma. Sin «validar con…» ni «escalar a…»: el equipo que ejecuta la herramienta es el que decide.
- **Menciones a otras áreas:** solo cuando cambian la acción. Storage en `path-dead` y el dueño de la VM en `snap-age` y `vm-off` (antes de eliminar).
- **Control:** `Test-Reports.ps1` falla si un hallazgo queda sin sugerencia, si una entrada no se usa, si un texto está vacío o si un texto menciona un área fuera de esas excepciones.

## Del hallazgo a la acción

1. Ejecutar el comando de verificación para confirmar el hallazgo.
2. Solicitar a Claude el plan de cambio (`/health` lo ofrece al finalizar).
3. Las acciones destructivas en producción (eliminación de snapshots, apagado de VMs, mantenimiento de hosts) las ejecuta una persona con cambio aprobado y confirmación del responsable.
