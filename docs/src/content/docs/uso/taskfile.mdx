`Taskfile.yml` reúne las tareas habituales en comandos cortos para ejecutarlos desde una terminal, fuera de Claude Code. Requiere [Task](https://taskfile.dev):

```powershell
winget install Task.Task
```

`task` sin argumentos muestra la lista de tareas.

## Tareas disponibles

| Tarea | Variables | Script |
|---|---|---|
| `task setup` | — | Activa el control `pre-commit` y crea `config/environments.json` desde el ejemplo si no existe |
| `task install` | — | `Install-Govc.ps1` |
| `task credential` | `ENV`, `ACCOUNT` (opcional) | `Set-GovcCredential.ps1` (no se ejecuta dentro de Claude Code) |
| `task env` | `ENV` | `govc.ps1 -Env <ENV> about` |
| `task vcsim` | — | Simulador en `https://127.0.0.1:8989/sdk` |
| `task report` | `ENV` o `FROM`, `TYPE` (`all` por defecto) | `New-Report.ps1` |
| `task inventory` · `health` · `capacity` · `snapshots` | `ENV` o `FROM` | `New-Report.ps1 -Type <tipo>` |
| `task host-check` | `ENV` o `FROM`, `CLUSTER` (opcional) | `Invoke-HostCheck.ps1` |
| `task audit` | `ENV` o `FROM`, `SCOPE` (`full` por defecto), `CLUSTER` (opcional) | `Invoke-Audit.ps1` |
| `task trend` | `ENV` | `Compare-Report.ps1` |
| `task demo` | — | `New-DemoData.ps1` y los reportes de inventario, hosts y auditoría sobre esos datos |
| `task test` | — | `Test-Guards.ps1` y `Test-Reports.ps1` |
| `task test:guards` · `test:reports` · `test:log` | — | Prueba individual |
| `task docs` · `docs:build` | — | Servidor local o compilación de esta documentación |

Las variables se indican como `NOMBRE=valor`. Los reportes requieren `ENV` (consulta el entorno) o `FROM` (vuelve a analizar una carpeta ya recolectada en `reports/`, sin consultar vCenter); sin ninguna de las dos, la tarea se cancela. `TYPE` y `SCOPE` solo admiten los valores del script; un valor distinto cancela la tarea antes de ejecutar nada.

`task credential` registra o reemplaza la credencial de un entorno. La contraseña la solicita `cmdkey` por consola y nunca pasa por argumentos. La tarea no expone `-Remove` ni parámetros libres; para eliminar una credencial se utiliza el script directamente, como se indica en [Configuración](/vcenter/inicio/configuracion/). Dentro de Claude Code, la tarea se cancela antes de ejecutar el script.

## Ejemplos

```powershell
task health ENV=prod
task report ENV=prod TYPE=inventory -- -Format csv
task snapshots ENV=prod -- -SnapshotWarnDays 3
task host-check ENV=prod CLUSTER=CL-PROD-01
task audit ENV=prod SCOPE=security
task health FROM=reports/prod/20261017-080000
task demo
task install -- -WithVcsim
```

Los parámetros adicionales del script se escriben después de `--` y se pasan sin cambios. Para revisar el comando que se ejecutaría sin ejecutarlo: `task --dry <tarea> …`.

## Alcance

:::caution[Solo operaciones sin cambios en vCenter]
El Taskfile no incluye tareas que modifiquen vCenter ni una tarea genérica que pase subcomandos al wrapper. En los entornos `confirm`, la aprobación de las escrituras depende del hook de Claude Code, que no ve lo que ejecuta una tarea. Los cambios y la provisión siguen el [flujo con validación y aprobación](/vcenter/provision/flujo/).
:::

Claude Code no utiliza estas tareas: invoca los scripts y el wrapper directamente, para que las guardas evalúen cada operación. Las ejecuciones hechas con Task pasan por `scripts/govc.ps1` igual que cualquier otra, de modo que aplican el modo del entorno y quedan registradas en la bitácora.
