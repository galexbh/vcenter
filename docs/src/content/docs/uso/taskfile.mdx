`Taskfile.yml` reúne las tareas habituales en comandos cortos para ejecutarlos desde una terminal, fuera de Claude Code. Requiere [Task](https://taskfile.dev):

```powershell
winget install --id Task.Task -e
```

Después de instalarlo, abrir una terminal nueva para que `task` quede disponible en el `PATH`. `task` sin argumentos muestra la lista de tareas.

## Tareas disponibles

| Tarea | Variables | Script |
|---|---|---|
| `task setup` | — | Activa el control `pre-commit` y crea `config/environments.json` desde el ejemplo si no existe |
| `task install` | — | `Install-Govc.ps1`: la versión estable más alta de govc; `-- -Version vX.Y.Z` fija una versión y `-- -WithVcsim` agrega el simulador |
| `task credential` | `ENV`, `ACCOUNT` (opcional) | `Set-GovcCredential.ps1` (no se ejecuta dentro de Claude Code) |
| `task credential:list` | — | `Set-GovcCredential.ps1 -List`: destino, estado y usuario por entorno, sin contraseñas |
| `task credential:remove` | `ENV` | `Set-GovcCredential.ps1 -Env <ENV> -Remove`, con confirmación previa |
| `task env` | `ENV` | `govc.ps1 -Env <ENV> about` |
| `task vcsim` | — | Simulador en `https://127.0.0.1:8989/sdk` |
| `task report` | `ENV` o `FROM`, `TYPE` (`all` por defecto) | `New-Report.ps1` |
| `task inventory` · `health` · `capacity` · `snapshots` | `ENV` o `FROM` | `New-Report.ps1 -Type <tipo>` |
| `task host-check` | `ENV` o `FROM`, `CLUSTER` (opcional, solo con `ENV`) | `Invoke-HostCheck.ps1` |
| `task perf` | `ENV` o `FROM`, `WINDOW` (opcional: `1h`, `24h` o `7d`; `24h` por defecto; solo con `ENV`), `CLUSTER` (opcional, solo con `ENV`) | `Invoke-PerfCheck.ps1` |
| `task audit` | `ENV` o `FROM`, `SCOPE` (opcional: `full`, `security`, `capacity` o `performance`; sin él, `full` con `ENV` y el alcance guardado con `FROM`), `WINDOW` (opcional, ventana de rendimiento, solo con `ENV`), `CLUSTER` (opcional, solo con `ENV`) | `Invoke-Audit.ps1` |
| `task trend` | `ENV` | `Compare-Report.ps1` |
| `task demo` | — | `New-DemoData.ps1` y los reportes de inventario, hosts, rendimiento y auditoría sobre esos datos |
| `task test` | — | `Test-Guards.ps1` y `Test-Reports.ps1` |
| `task test:guards` · `test:reports` · `test:log` | — | Prueba individual; `task test:guards -- -Strict` cuenta como falla cualquier grupo omitido |
| `task docs` | — | Servidor local de esta documentación en `http://localhost:4321/vcenter/` |
| `task docs:build` | — | Compilación de esta documentación en `docs/dist/` |

Las variables se indican como `NOMBRE=valor`. Los reportes requieren `ENV` (consulta el entorno) o `FROM` (vuelve a analizar una carpeta ya recolectada en `reports/`, sin consultar vCenter).

### Validación de variables

Antes de ejecutar nada, cada tarea valida sus variables y se cancela con un mensaje si no cumplen:

| Condición | Mensaje |
|---|---|
| Ni `ENV` ni `FROM` | `Indica ENV=<entorno> o FROM=<carpeta en reports/>` |
| `ENV` y `FROM` a la vez | `Indica ENV o FROM, no ambos` |
| `ENV` con caracteres distintos de letras, números, guion o guion bajo | `ENV solo admite letras, números, guion y guion bajo` |
| `CLUSTER` o `WINDOW` junto con `FROM` (`host-check`, `perf`, `audit`) | `CLUSTER y WINDOW solo aplican con ENV (con FROM se usa lo ya recolectado)` |
| `TYPE`, `SCOPE` o `WINDOW` con un valor que el script no admite | `TYPE admite all, inventory, snapshots, capacity o health`, y equivalentes para `SCOPE` y `WINDOW` |

Los valores de las variables llegan a PowerShell como variables de entorno (`T_ENV`, `T_FROM`, `T_TYPE`, `T_CLUSTER`, `T_WINDOW`, `T_SCOPE`, `T_ACCOUNT`) y nunca se insertan en el texto del comando: un nombre de clúster o una carpeta con comillas o `$` no rompe el comando ni inyecta código. Los parámetros adicionales después de `--` sí se agregan al comando tal como se escriben.

`task credential` registra o reemplaza la credencial de un entorno. La contraseña la solicita `cmdkey` por consola y nunca pasa por argumentos. `task credential:list` muestra las credenciales registradas sin revelar contraseñas, y `task credential:remove` elimina la de un entorno tras pedir confirmación (ver [Configuración](/vcenter/inicio/configuracion/)). Ninguna de las tres admite parámetros libres y todas se cancelan dentro de Claude Code antes de ejecutar el script.

## Ejemplos

```powershell
task health ENV=prod
task report ENV=prod TYPE=inventory -- -Format csv
task snapshots ENV=prod -- -SnapshotWarnDays 3
task host-check ENV=prod CLUSTER=CL-PROD-01
task perf ENV=prod WINDOW=24h
task perf ENV=prod CLUSTER=CL-PROD-01 WINDOW=1h
task audit ENV=prod SCOPE=security
task audit ENV=prod SCOPE=performance WINDOW=7d
task health FROM=reports/prod/20261017-080000
task perf FROM=reports/prod/20261018-090000 -- -DsLatencyWarnMs 15
task demo
task install -- -WithVcsim
```

Los parámetros adicionales del script se escriben después de `--` y se pasan sin cambios. Para revisar el comando que se ejecutaría sin ejecutarlo: `task --dry <tarea> …` (los valores de las variables aparecen como `$env:T_…`, no en el texto). `task docs` y `task docs:build` instalan las dependencias de la documentación solo cuando faltan o cuando cambia `docs/package-lock.json`.

## Alcance

:::caution[Solo operaciones sin cambios en vCenter]
El Taskfile no incluye tareas que modifiquen vCenter ni una tarea genérica que pase subcomandos al wrapper. En los entornos `confirm`, la aprobación de las escrituras depende del hook de Claude Code, que no ve lo que ejecuta una tarea. Los cambios y la provisión siguen el [flujo con validación y aprobación](/vcenter/provision/flujo/).
:::

Claude Code no utiliza estas tareas: invoca los scripts y el wrapper directamente, para que las guardas evalúen cada operación. Las ejecuciones hechas con Task pasan por `scripts/govc.ps1` igual que cualquier otra, de modo que aplican el modo del entorno y quedan registradas en la bitácora.
