## Clasificación de subcomandos

`scripts/lib/Classify.psm1` asigna una clase a cada invocación. **Toda operación que no se reconoce como lectura se trata como modificación.**

| Clase | Regla | Ejemplos |
|---|---|---|
| `read` | Lista explícita o sufijos `.info`, `.ls`, `.tree` | `about`, `ls`, `find`, `object.collect`, `events`, `tasks`, `metric.sample`, `vm.info`, `snapshot.tree` |
| `write` | Cualquier otra | `vm.clone`, `vm.create`, `vm.change`, `vm.power -on`, `snapshot.create`, `tags.attach`, `folder.create` |
| `destructive` | Lista explícita o verbo final `destroy`, `rm`, `remove`, `delete`, `unregister`, `shutdown`, `reboot`, `revert`, `disconnect`, `detach`, `erase`, `purge` | `vm.destroy`, `snapshot.remove`, `datastore.rm`, `host.maintenance.enter`, `vm.power -off/-s/-r/-reset/-suspend` |
| `secret` | Expone credenciales o sesión, o redirige la conexión | `env`, `vm.console`, `session.login`, `sso.service.ls`, todo `guest.*`, flags de volcado o de conexión (ver abajo) |

Reglas particulares:

- **Flags secretos, en cualquier subcomando (incluido `host.esxcli`):** `-password`, `-debug`, `-dump-cookie`, `-trace`, `-verbose`, `-persist-session` y los que cambian la conexión: `-u`, `-k`, `-insecure`, `-tls-ca-certs`, `-tls-known-hosts`, `-cert`, `-key`, `-vim-version` y `-vim-namespace`. Con ellos, la credencial del wrapper podría enviarse a otro endpoint o con otra validación de certificados, o quedar en un volcado de tráfico; la conexión la define siempre el perfil.
- `guest.*` es `secret`: opera dentro del sistema operativo invitado con credenciales del guest (`-l usuario:clave`).
- `vm.question` es `read`; con `-answer` es `write`, porque responde la pregunta pendiente de la VM y cambia su estado.
- `vm.power` es `write` únicamente con `-on`; cualquier otra combinación es `destructive`.
- `host.esxcli` se clasifica por el verbo del comando esxcli: `list` y `get` son `read`; cualquier otro, `destructive`; `system settings encryption` es `secret`. Ver [esxcli vía govc](/vcenter/uso/esxcli/).

## Decisiones del hook

Prevalece siempre la decisión más restrictiva.

`.claude/settings.json` registra dos entradas `PreToolUse`:

| Matcher | Hook | Intérprete | Tiempo máximo | Ante falla |
|---|---|---|---|---|
| `Bash\|PowerShell\|Monitor\|Write\|Edit\|NotebookEdit` | `.claude/hooks/pre-guard.sh` → `.claude/hooks/govc-guard.ps1` | `sh` y `pwsh` | 30 s | Bloquea |
| `Read\|Glob\|Grep` | `.claude/hooks/read-guard.sh` | `sh` | 10 s | Bloquea |

Ambas entradas declaran `"onFailure": "block"` (requiere Claude Code 2.1.295 o posterior): si el hook falla, no encuentra su intérprete o supera el tiempo máximo, la llamada se bloquea en lugar de continuar sin control.

### Filtro rápido (`pre-guard.sh`)

Iniciar PowerShell cuesta unos 0,6 s por llamada. `pre-guard.sh` revisa primero el texto de la llamada y solo inicia `govc-guard.ps1` si contiene alguna palabra relevante: `govc`, `govmomi`, `password`, `cred`, `vault`, `cmdkey`, `pwsh`, `powershell`, `base64`, `logs`, `git`, `environments`, el nombre de la API de la bóveda de Windows o una comilla invertida (PowerShell elimina escapes como ``g`ovc`` antes de que la guarda lea el texto). Toda decisión de `govc-guard.ps1` (`deny`, `ask` o `allow`) exige alguna de esas palabras; sin ellas, la guarda saldría sin decidir, y el filtro sale igual sin iniciar PowerShell. `Test-Guards.ps1` comprueba que ambos caminos den la misma decisión en todos los casos.

### Comandos (Bash, PowerShell y Monitor)

| Situación | Decisión |
|---|---|
| Secretos en el comando, govc directo, entorno no definido | `deny` |
| `destructive` fuera de `lab` · `write` en `readonly` · `secret` | `deny` |
| Comandos codificados o ejecución de código decodificado | `deny` |
| Escritura, movimiento o eliminación en `logs/` | `deny` |
| `git add -f`, o `git add` de `reports/`, `logs/` o `environments.json` | `deny` |
| `write`, o `destructive` en `lab` | `ask` |
| Entorno o subcomando en una variable | `ask` |
| Solo lecturas con el wrapper y cmdlets de transformación, en PowerShell | `allow` |
| Lectura combinada con otros comandos, redirecciones o llamadas a métodos | Flujo normal de permisos |

Cmdlets de transformación admitidos para la aprobación automática: `ConvertFrom-Json`, `ConvertTo-Json`, `Select-Object`, `Where-Object`, `Sort-Object`, `Group-Object`, `Measure-Object`, `Format-Table`, `Format-List`, `Out-String`, `Select-String`, `ForEach-Object` y `ConvertFrom-GovcCollect`. También se admite `Import-Module ./scripts/lib/GovcJson.psm1`, solo con esa ruta literal y, opcionalmente, `-Force`. Los comandos contenidos en sus bloques también se validan.

### Permisos de `.claude/settings.json`

Además de los hooks, las reglas de permisos establecen:

| Tipo | Reglas |
|---|---|
| `allow` | Scripts de reportes, auditoría, tendencias, demo y pruebas, y `npm --prefix docs run build` |
| `ask` | Editar `scripts/govc.ps1`, `config/environments.json`, `.claude/skills/**`, `.claude/commands/**` y `.githooks/**`; ejecutar `New-Report.ps1`, `Invoke-HostCheck.ps1`, `Invoke-PerfCheck.ps1`, `Compare-Report.ps1` o `New-DemoData.ps1` con `-OutDir`, que puede escribir fuera de `reports/` |
| `deny` | Editar `logs/**`, `scripts/lib/**`, `.claude/hooks/**` y `.claude/settings.json`; leer las sesiones guardadas de govmomi; `cmdkey` (en PowerShell y Bash) y el script de registro de credenciales; `git add -f` |

Las reglas `Edit(ruta)` también cubren la herramienta Write (Claude Code solo consulta reglas `Edit` para escrituras de archivos), por lo que no se declaran reglas `Write(ruta)`. `disableSkillShellExecution` impide que las skills ejecuten comandos de shell al cargarse.

### Archivos (Write, Edit y NotebookEdit)

El hook revisa el contenido que Claude escribe y bloquea cualquier archivo que acceda a la bóveda de credenciales o defina la contraseña de govc. Así se evita que el control de comandos se eluda mediante un script nuevo.

### Lecturas (Read, Glob y Grep)

Una guarda liviana en `sh` (`.claude/hooks/read-guard.sh`) bloquea la lectura de la carpeta de sesión efímera y de las sesiones guardadas de govmomi. Se separó del hook de PowerShell porque este agregaba unos 600 ms a cada lectura; la versión en `sh` tarda alrededor de 100 ms.

### Limitación conocida: texto descriptivo

Las reglas de archivos se aplican a **cualquier** contenido, incluida la documentación. Un texto que mencione literalmente la ruta de la carpeta de sesión o las variables de sesión de govc se bloquea aunque sea solo descriptivo. Se mantiene así a propósito: limitar la regla por extensión permitiría escribir código en un archivo de texto y ejecutarlo de otra forma. Al documentar, se describe la carpeta en palabras («carpeta temporal privada del lote») en lugar de su nombre literal.

### Limitación conocida: exclusiones del control pre-commit

La búsqueda de credenciales en el contenido agregado de `.githooks/pre-commit` excluye `scripts/Test-Guards.ps1`, `.claude/hooks/govc-guard.ps1` y `.githooks/*`, porque contienen patrones de ejemplo que de otro modo bloquearían el commit. Una credencial real agregada a esos archivos no se detectaría; los cambios en ellos requieren revisión manual del diff antes de confirmarlos.

## Mantenimiento de las guardas

Claude no puede modificar `scripts/lib/`, `.claude/hooks/` ni `.claude/settings.json`, y la edición de `scripts/govc.ps1` requiere aprobación. Los cambios a estas piezas se preparan para revisión y los aplica una persona.

## Pruebas

```powershell
./scripts/Test-Guards.ps1           # o bien: task test:guards
./scripts/Test-Guards.ps1 -Strict   # o bien: task test:guards -- -Strict
```

El script ejecuta los casos de clasificación y del hook contra `config/environments.example.json`, sin contactar vCenter, y comprueba que `pre-guard.sh` y `govc-guard.ps1` tomen la misma decisión. Con `-Strict`, un grupo de casos omitido (por ejemplo, porque falta `sh` o se prueba un hook anterior) cuenta como falla; se recomienda antes de instalar guardas nuevas. Debe agregarse un caso por cada regla nueva o modificada.

:::tip
Cuando una guarda bloquea una acción legítima, Claude explica el motivo y entrega el comando para que lo ejecute una persona. No intenta eludir el control.
:::
