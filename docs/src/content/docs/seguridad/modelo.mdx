## Capas de control

| Capa | Componente | Riesgo que mitiga |
|---|---|---|
| Punto único de acceso | `scripts/govc.ps1` | Credenciales en disco o en variables persistentes; operaciones fuera del modo del entorno; acciones sin registro |
| Control previo de comandos | `.claude/hooks/pre-guard.sh` → `.claude/hooks/govc-guard.ps1` (tools Bash, PowerShell y Monitor) | Ejecución directa de govc, exposición de secretos, cambios destructivos, escrituras en entornos de solo lectura, comandos codificados, alteración de la bitácora |
| Control previo de archivos | `.claude/hooks/pre-guard.sh` → `.claude/hooks/govc-guard.ps1` (tools Write, Edit y NotebookEdit) | Creación por Claude de scripts que accedan a la bóveda de credenciales |
| Control previo de lecturas | `.claude/hooks/read-guard.sh` (tools Read, Glob y Grep) | Lectura por Claude de la carpeta de sesión efímera del modo lote y de las sesiones guardadas de govmomi en el perfil del usuario |
| Falla cerrada de los hooks | `"onFailure": "block"` en ambos hooks (Claude Code 2.1.295 o posterior) | Un hook que falla, no encuentra `sh` o `pwsh`, o excede su tiempo máximo deja pasar la llamada sin control |
| Clasificador | `scripts/lib/Classify.psm1` | Subcomandos nuevos o desconocidos (se tratan como modificación); flags que vuelcan tráfico o redirigen la conexión; operaciones en el SO invitado (`guest.*`) |
| Permisos de Claude Code | `.claude/settings.json` | Modificación de guardas, bitácoras o configuración (la edición de `config/environments.json`, `scripts/govc.ps1`, skills, comandos y `.githooks/` requiere aprobación); `cmdkey`; lectura de sesiones de govc |
| Control de versiones | `.gitignore`, `.githooks/pre-commit` | Reportes, bitácoras, configuración real o credenciales en el repositorio |
| Integridad de la bitácora | Encadenamiento SHA-256 + `scripts/Test-AuditLog.ps1` | Edición, eliminación o inserción no detectada de registros |

## Modos de entorno

| Clase de operación | `readonly` | `confirm` | `lab` |
|---|---|---|---|
| **read** (lectura) | Automática | Automática | Automática |
| **write** (modificación) | Bloqueada | Requiere aprobación | Requiere aprobación |
| **destructive** (destructiva) | Bloqueada | Bloqueada para Claude; una persona en terminal interactiva, con confirmación | Requiere aprobación |
| **secret** (expone credenciales) | Bloqueada | Bloqueada | Bloqueada |

## Flujo de una operación

```text
Propuesta de Claude:  ./scripts/govc.ps1 -Env prod vm.clone -vm tpl app02
        │
        ▼
Filtro pre-guard ── el texto contiene "govc": inicia la guarda de PowerShell
        ▼
Hook govc-guard ── analiza el comando, identifica -Env y el subcomando
        │          clase: write · modo prod: confirm
        │          ⇒ "ask": Claude Code solicita aprobación
        ▼
Wrapper govc.ps1 ── vuelve a validar el modo (defensa en profundidad)
        │           registra "started" en la bitácora (sin registro, no ejecuta)
        │           obtiene govc:prod de Credential Manager
        │           quita las GOVC_*/GOVMOMI_* heredadas, define las del perfil
        │           solo para el proceso y ejecuta tools/govc.exe
        │           restablece las variables y registra el resultado
        ▼
logs/audit-AAAAMMDD.jsonl (encadenado)
```

## Bitácora de auditoría

Cada invocación del wrapper agrega una línea JSON. El campo `prev` contiene el SHA-256 de la línea anterior, lo que encadena todos los registros:

```json
{"prev":"9f2c…e41a","ts":"2026-10-17T08:51:23-06:00","user":"DOMINIO\\usuario","claude":true,"env":"prod","mode":"confirm","class":"read","command":"about","result":"ok","exitCode":0}
```

| Campo | Contenido |
|---|---|
| `prev` | Hash del registro anterior (`GENESIS` en el primero) |
| `ts`, `user`, `claude` | Fecha, usuario de Windows (identidad del proceso, no variables de entorno) e indicador de ejecución por Claude |
| `env`, `mode`, `class` | Entorno, modo y clase de la operación |
| `command` | Comando con argumentos sensibles enmascarados: `-password` siempre, `-p` solo dentro de `host.esxcli` y `-l` solo en `guest.*` (`find -p` no se enmascara) |
| `result`, `exitCode` | `started` (escrituras y destructivos, antes de ejecutarse, con `exitCode` `-1`), `ok`, `error`, `blocked-secret`, `blocked-readonly`, `blocked-destructive`, `blocked-batch-<clase>` o `cancelled`, y código de salida |
| `batch` | Identificador del lote, en las líneas del modo lote |

Las escrituras y los destructivos se registran **antes** de ejecutarse: si la línea `started` no puede escribirse, el wrapper no ejecuta la operación. Así, toda modificación ejecutada tiene evidencia previa en la bitácora, aunque el proceso se interrumpa.

**Verificación de integridad:**

```powershell
./scripts/Test-AuditLog.ps1
# Bitácora íntegra: 412 líneas en 6 archivo(s).
```

Si un registro se edita, elimina o inserta, el script indica el archivo y la línea donde se rompe la cadena.

:::note[Alcance del control]
El encadenamiento **detecta** la manipulación, pero no la impide. Para una retención con garantía de inalterabilidad, se recomienda enviar la bitácora a un repositorio central de solo escritura (SIEM), según la política de Seguridad de la Información.
:::

## Contenido no confiable

Los nombres, anotaciones, eventos y textos de alarma provienen de vCenter y pueden ser escritos por terceros. Claude los trata **siempre como datos y nunca como instrucciones**. En los reportes, el contenido se codifica en HTML y se escapa en Markdown para impedir la inyección de enlaces o formato; en CSV se neutralizan las fórmulas. Los comandos de revisión sugeridos identifican los objetos por referencia `Tipo:id` y escapan cualquier otro texto de vCenter como literal de PowerShell, de modo que un nombre con comillas, `;` o `$` no altera el comando al copiarlo (ver [comandos de revisión](/vcenter/reportes/generar/#comandos-de-revisión)).
